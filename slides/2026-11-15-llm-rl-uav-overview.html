壱
為什麼要結合 LLM 與 RL
兩者剛好互補，但直接接在一起有代價

補各自擅長、各自缺什麼

LLM

擅長全局語意、任務分解、自然語言溝通

缺點延遲高、會幻覺、不會從互動中學

例：Qwen2.5-7B 未微調時會輸出 "go to target point #8, #8" 這類非法指令

RL / MARL

擅長即時連續控制、從互動中學習

缺點只看局部觀測、溝通是黑箱、泛化差、收斂慢

例：MATD3 缺乏全局態勢感知；純 MARL 隊伍變大時表現退化

三篇 core 論文的出發點都一樣：讓 LLM 補 RL 的全局語意，讓 RL 補 LLM 的即時性與可靠度。
出處：wang2025rally（RALLY）・dong2026hierarchical（LLM-MATD3）・ahn2026hallucination（SafeGPT）

①LLM-MATD3：LLM 分派任務、MATD3 執行

任務5 vs 5 多無人機對抗（2D、固定高度）

  • LLM 每 300 步分派任務：追擊／區域防守／支援，並選隊形
  • 任務標籤轉成 embedding，同時接進 actor 和 critic；每種任務有專屬 reward
  • LLM：DeepSeek-R1 14B，用約 3000 筆模擬樣本 LoRA 微調、本機執行
  • 最佳任務比例 55 : 35 : 10（交換比 2.59）

勝率

LLM-MATD382%
MATD369%
MADDPG55%
MAPPO42%

對手是專家規則系統，不會學習

出處：dong2026hierarchical（2026）

②SafeGPT：用 Safe-RL 擋住 LLM 的幻覺

任務10 台無人機巡訪 500～2000 個航點（3D 區域）

  • GPT-4o 把航點分區 → 每台機上的 GPT-4o-mini 排順序
  • Safe-RL（CMDP + Lagrangian actor-critic）檢查每條路線的電量、通訊、重複造訪，違規就退回重規劃
  • 最佳權重下，SNR 與電量違規率都只有 0.3%

N = 2000 的累積能耗（× 10⁷ kJ）

SafeGPT2.24
GPT-Only3.54
DQN9.39
Actor-Critic11.2

越短越好。只用 LLM 多耗 58%

出處：ahn2026hallucination（2026）

③RALLY：LLM 語意協商 + MARL 選角色

任務集群躲避追擊者，同時用隊形覆蓋目標區

  • 每台無人機用 LLM 以結構化自然語言和鄰居協商共識目標
  • RMIX（值分解）結合 LLM 先驗與線上經驗，動態切換 Commander／Coordinator／Executor
  • GPT-4o 收集資料 → LoRA 微調 Qwen2.5；1.5B 在效果和延遲之間最平衡

泛化

集群 8 → 11 台時，純 MARL 的 CI-HRL 退化，RALLY 維持表現

消融

三角色 > 雙角色 > 無角色；未微調的 LLM 會輸出非法指令

論文以圖呈現結果，正文沒有具體百分比（待確認）。有 SITL 驗證

出處：wang2025rally（IEEE OJVT 2025）

④LLM 只在訓練時當老師

LAMARL adjacent・地面機器人

  • LLM（o1-preview）寫先驗策略函數和 reward 函數，交給 MADDPG 訓練
  • 先驗策略讓樣本效率平均 +185.9%
  • CoT + 基本 API 讓函數產生成功率 1% → 68.5%
  • 8 台全向輪機器人實機驗證

lou 2026 adjacent・電力交易

  • LLM 工作流寫程式、呼叫求解器，產生專家策略
  • MARL 用 Wasserstein 距離模仿專家
  • LLM 開銷集中在訓練；執行時只用輕量網路
兩個不同領域都證明可行，執行時零 LLM 延遲。無人機機上算力有限，最需要這種做法，但目前收錄的無人機論文還沒有人用。
出處：zhu2025lamarl（IEEE RA-L 2025）・lou2026llm（2026）——皆為 adjacent，不作為 UAV 證據

研究缺口與爭議
以下缺口是根據 13 篇論文的推論，還需要專門搜尋確認

隙研究缺口（候選題目）

1. 無人機上的「LLM 當老師」

LLM 離線產生航線、分派方案或先驗策略程式碼，MARL 模仿，執行時零延遲。LAMARL 的框架可以直接搬到集群隊形任務

2. RL 微調 LLM 本身

用 RLHF / GRPO 讓 LLM 直接做無人機決策——收錄的論文裡完全沒有

3. ① + ② 合併

LLM 指導 RL 的同時，再用 Safe-RL 檢查 LLM 的指令

4. RL 決定何時呼叫 LLM

呼叫頻率由學習決定，而不是固定每 300 步或每 25 步

另外：缺少和古典規劃 baseline 的比較；沒有自我對弈的對手；3D 動力學和實機延遲都沒驗證

💭 根據 wiki llm-rl-coupling-patterns、overview 的推論，非論文結論；參考 zhu2025lamarl・lou2026llm・yu2025conavgpt

議文獻之間的矛盾

CI-HRL 的泛化能力

RALLY 說集群 8 → 11 台時，CI-HRL 明顯退化（習慣性分群）

CI-HRL 說擴展到 15 台時，導航和躲避表現大致穩定

兩篇的指標不同，不算直接矛盾；引用 RALLY 的泛化優勢時要小心

MAPPO 好不好用

dong 說MAPPO 勝率 42%，在四個方法裡最差

CI-HRL 說MAPPO 穩定、計算效率高，仍是實際系統的主流選擇

任務不同，不一定衝突：MAPPO 單獨用在複雜多任務上收斂差，加上階層或交替訓練後可用

出處：wang2025rally・xiang2025decentralized・dong2026hierarchical；wiki cooperative-navigation、ppo 的「爭議與矛盾」段

結重點整理與下一步

  • 主流是LLM 在上、RL 在下；差別在兩者怎麼接（四種模式）
  • 各篇都在處理 LLM 的延遲與幻覺：降頻、RL 把關、蒸餾、只在訓練時用
  • 領域還很早期：core 只有 3 篇，全是多機、全在模擬
  • 最清楚的缺口：無人機上的「LLM 當老師」、RL 微調 LLM

  • 針對兩個缺口各做一次專門搜尋，確認「真的沒人做過」
